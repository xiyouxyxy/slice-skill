# 切片计划 · 完整示例

下面三个示例供执行时模式匹配。每个示例给出：用户输入 → 澄清 → WBS → 排程 → 落档要点。

---

## 示例 1：目标型（默认节奏，无时长无截止日）

**用户输入**：我想三个月学会用 Python 做数据分析，平时下班后才有空。

**规划前访谈（步骤 0.2，学习型必问）**：
- 基础水平 → 零基础（全量排，不跳模块）
- 完成定义 → "能独立做一个数据清洗 + 可视化的小项目"（写进最后一里程碑的「交付卡」判定标准）
- 每日时长 → 用户说"下班后才有空"，选 1h/天（默认）
- 期望完成日期 → 未给（默认节奏，随时可加）

**澄清（已并入访谈）**：基础与完成定义已在 0.2 收集，不再单独追问。

**WBS**（含三件套卡片样本）：
- M1 环境 + Pandas 基础（10 任务）
- M2 NumPy 与清洗（8 任务）
- M3 可视化（8 任务）
- M4 实战项目（6 任务）
- M5 复盘（4 任务）
- 共 36 个原子任务，总工时 ~54h（含验收）。

> 学习类前置问询可选：本例用户跳过，由 LLM 在 M1 头部补 `前置：Python 3.11+ 已装、pandas 可 import` 即可。

**排程**：无截止日、无每日时长 → 默认节奏（学习类：每周 5 可用日、每天 1 任务，约 0.5–1h）。
预计完成日 ≈ 今天 + 36 个可用日 ≈ 7–8 周（比用户"三个月"预期更快，提示：可保持默认，也可加量提前）。

**复习 / 缓冲**：每 5 天插 1 缓冲日；学习类内容按 +1 / +3 / +7 插入复习。

**三件套卡片样本**（完整 `.md` 文件里每张任务都长这样）：

```
### 2026-08-07 周五 · M1: Python 语法回顾（变量·类型·控制流） [1.0h]

- **子目标**：
  - [ ] 能区分可变/不可变类型（int / str / list / tuple）
  - [ ] 能写出 if / elif / else 嵌套
  - [ ] 能用 for / while + break / continue
- **验收**：3 道题
  - [ ] 变量交换（不引临时变量）
  - [ ] FizzBuzz（1–100）
  - [ ] 列表去重（保留顺序）
- **口述自检**：
  - [ ] 口述「列表 vs 元组的区别」
  - [ ] 口述「continue vs break 的区别」
- **状态**：⬜ → 🟡 → ✅
```

> 口述自检由规划 LLM 现生成，命中当天**最易混 / 最反直觉**的点（如上「列表 vs 元组」「continue vs break」「为什么字符串不可变却能用 + 拼接」），而不是泛泛的「讲讲今天收获」。

**落档**：`.slice/plans/learn-python.md`，每日表含"新内容/复习/缓冲/微任务"四类，每张任务都有三件套卡片。

**日常使用（最高频）**：用户说「今天做什么 / 今日打卡」→ 按 SKILL 9.1 今日视图抽当日卡片、展示三件套 → 询问完成情况 → 按 9.2 回写状态 / 必要时重排。导出时先 `python scripts/plan_to_events.py --in learn-python.md --out learn-python-events.json`，再跑 `export_html.py` / `export_ics.py`。

## 示例 2：课程型（有提纲 + 有截止日 + 有每日时长）

**用户输入**：这门课有 12 章提纲，我想 6 周内学完。工作日每天 1h，周末每天 2h。

**提纲映射**：12 章直接作为任务单元；按章节估总工时 ~48h。
可用日产能 = 5×1 + 2×2 = 9h/周 × 6 周 = 54h ≥ 48h → 可行。

**排程**：有截止日 + 有时长 → 每周排 2 章新内容（~8h）+ 周末复习；第 6 周缓冲 / 收尾。
每章学完后 +1 / +3 / +7 天插入复习（计入当日时长）。

**预警检查**：单日负荷 ≤ 2h，未超 2.5h 上限，不预警。

**落档**：`.slice/plans/<course-slug>.md`。

## 示例 3：长期任务 / 项目型（无固定每天时间）

**用户输入**：我想写一本书，今年内写完初稿，没固定每天时间。

**类型判定**：项目（长期任务）。（注意：它虽是「长期」，但有线性 WBS 与里程碑，属项目型，不是习惯型——真正的习惯型见示例 4。）

**前置条件问询（项目型必问）**：
> 完成写书，你手上已有哪些工具 / 账号 / 权限 / 数据 / 素材？还缺什么？

用户：「有大纲和素材笔记，缺一个写作软件（打算用 Obsidian），出版社合同还没签。」

→ 落档 `## 前置条件` 节：工具 = Obsidian（待装）；行政 = 出版社合同（待签，长周期，第 1 周发起）；数据 / 素材 = 大纲 + 素材笔记（已齐）。前 1–2 个里程碑即「装 Obsidian + 搭写作模板」「发起出版社合同洽谈」，打通工具与行政门槛再进正文。

**WBS**：大纲 → 逐章草稿（按章拆原子任务）→ 修订 → 统稿；共约 40 个原子任务。

**排程**：无时长无截止日 → 默认节奏（项目类：每周 5 日、每天 1–2 任务）。
预计完成日告知用户；并建议"设一个每周固定写作时段（如周六上午 3h）"以提速。

**兜底**：若用户中途说"这周完全没写"，走步骤 9 重排（缓冲消化 → 顺延），落后超 30% 时提示延长截止日或提高投入。

**落档**：`.slice/plans/write-book.md`，进度区追踪连续写作天数。

## 示例 4：习惯型（每日重复 + 连续打卡，无线性 WBS）

**用户输入**：我想养成每天冥想 10 分钟的习惯，先坚持 30 天看看。

**类型判定**：习惯。→ **步骤 0.2 用户访谈跳过**（不写 `## 用户画像` 节）；前置条件可留空。（与示例 1/2/3 的类型分流不同：习惯型不收集基础/完成定义/时长/日期四问。）

**结构特点（与学习 / 项目本质不同）**：

- **没有里程碑 / 线性 WBS**；核心是「每天重复同一动作 + 连续打卡（streak）」。
- 计划 = 30 张「Day N」日卡（每日一张），模板化、内容基本一致，只换日期与当天口述题。
- 进度区追踪「连续打卡天数 / 中断次数」，而不是「完成任务数」。

**WBS（习惯版三件套）**——按 SKILL 步骤 3 的「习惯类」映射：

| 三件套 | 习惯型写法 |
|--------|-----------|
| 子目标 | 动作项（今天要做的那个动作） |
| 验收 | 时长 / 频次（可量化的当日证据） |
| 口述自检 | 简短复盘（1 句话：什么会打断我、明天怎么排掉） |

**排程**：无截止日 → 默认节奏（习惯：每天 1 张日卡；周末不中断、可减半为 5 分钟）。预计完成日 = 今天 + 30 天。某天没做 → 该天标 `⏭`、连续天数归零、窗口顺延（总天数 +1），不补卡。

**三件套卡片样本**（Day 7）：

```
### 2026-09-12 周六 · 习惯 Day 7：冥想 10 分钟 [0.17h]

- **子目标**（今天要做的动作）：
  - [ ] 用计时器完成连续 10 分钟冥想（不分心刷手机）
  - [ ] 结束后在 App / 手账记「第 7 天」
- **验收**（量化证据）：
  - [ ] 冥想记录 ≥ 10:00，或手账「Day 7 ✅」
- **口述自检**（1 句话复盘）：
  - [ ] 口述「今天最容易让我中断的一件事，以及明天怎么提前排掉它」
- **状态**：⬜ → 🟡 → ✅
```

**落档**：`.slice/plans/meditation-30d.md`，进度区单列「连续打卡：N 天 / 中断：M 次」。

**日常使用**：用户说「今天打卡」→ 9.1 抽 Day N 卡 → 完成后 9.2 回写（`- [x]` + `**状态**` ✅ + 连续天数 +1）。中断那天标 `⏭`、连续天数归零。导出 HTML 勾完后用「导出回写指令」写回 `.md`（见 9.2 协议）。
